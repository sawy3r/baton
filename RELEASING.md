# Releasing Baton

Baton uses semantic versioning for normative protocol behavior and record
contracts.

- **Major** — a principle, responsibility boundary, required handoff, schema,
  or outcome meaning changes incompatibly.
- **Minor** — a backward-compatible optional capability or contract version is
  added.
- **Patch** — wording, examples, fixtures, or implementation changes preserve
  conforming behavior.

Release candidates use `v<version>-rc.<number>` annotated tags and GitHub
prereleases. A published tag is immutable.

## Candidate checklist

1. Start from the exact reviewed release head with a clean worktree and full
   Git history. Confirm `VERSION` matches the intended tag.
2. Install the pinned Python dependency in an isolated environment and run the
   full portable profile on Node 22 and Node 24:

   ```sh
   python3 -m venv .venv
   .venv/bin/python -m pip install -r conformance/requirements.txt
   .venv/bin/python conformance/check.py
   node --test test/records/*.test.mjs test/operations/*.test.mjs test/adapters/*.test.mjs test/install/*.test.mjs test/board/*.test.mjs test/driver/*.test.mjs test/dogfood/*.test.mjs test/release/*.test.mjs
   ```

3. Check generated bytes, historical overhead objects, installers, and the
   post-check tree:

   ```sh
   node scripts/generate-adapters.mjs --check
   node scripts/measure-overhead.mjs --check
   sh -n install-claude.sh
   sh -n install-codex.sh
   git diff --check
   git status --short
   ```

4. Review the diff from the prior tag. Confirm current docs, examples, schema,
   conformance manifest, package version, and release note agree. Historical
   notes and captures stay unchanged.
5. Run user-scope dry-runs for Claude Code and Codex from the frozen package.
   Installation tests use temporary homes and no live credentials.
6. If a real-machine cutover is in scope, snapshot managed paths, apply each
   install with explicit confirmation, validate both manifests and package
   digests, prove repeated install is a no-op, and run read-only discovery
   smokes. Record transaction identities and hashes, never configuration
   contents or credentials.
7. Merge the reviewed release candidate to the intended target under branch
   protection. Rerun every gate on the exact resulting commit.
8. Verify that the source and generated support-package tree are the tested
   bytes. Create the annotated tag on that exact commit, then publish the
   committed release note as a GitHub prerelease.
9. Verify the public tag, release assets, website links, current schema bytes,
   and archived schema URLs. Record the immutable commit an engine may pin.

If any check fails after merge but before tagging, stop. Fix and re-review; do
not create or move a best-effort tag.

## Portable versus autonomous claims

Portable success proves the package, records, operations, installers, board,
driver contract, dogfood harness, and deterministic budgets. It does not prove
an autonomous engine.

An engine conformance claim requires every autonomous case to run through the
engine’s actual binary, scheduler, persistence, workspace, driver, and Git
boundaries. `NOT RUN` is not PASS. Final `v1.0.0` waits for that evidence from
Sworn or another real engine.

## The 1.0 history boundary

The immutable `v0.16.0` tag preserves Baton 0.x. RC2’s Claude user installer
can transactionally migrate only the exact audited v0.16 package, command set,
and instruction block. That installer migration does not make 0.x delivery
records valid RC2 records.
