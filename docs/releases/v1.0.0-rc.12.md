# Baton v1.0.0-rc.12 — plain language and smoother repair loops

RC12 makes Baton easier to understand and removes two procedural traps without
changing what it protects.

The README, install guide, five skills, examples, errors, and read-only boards
now lead with:

1. what happened;
2. what it means;
3. what happens next; and
4. technical details when they are useful.

Verifier threads still start clean and independent. The
[direct-repair rule](../../baton/PROTOCOL.md#direct-repair-continuation) permits
bounded continuation after recorded `FAIL`; a fresh thread remains valid and
assembly verification still starts fresh.

The Protocol also defines a bounded
[exact-head refresh](../../baton/PROTOCOL.md#exact-head-refresh) after an
unreceipted track advance. An engine may return the slice to the Implementer to
record the exact current candidate without fabricating `FAIL`.

The release keeps the same five roles, operations, verdict tokens, plan and
receipt formats, and error codes. It adds no role, schema, gate, lifecycle
stage, recovery command, or language-checking process; it clarifies retry and
recovery routing inside the existing attempt model.

The normal four-handoff skill load is 1,506 fixed words, down from 1,509 in
RC11.
