# Baton v1.0.0-rc.10 — structural record reservation

RC10 makes standalone board projection ordinary and fail-closed. Candidate and
Verifier `PASS` state now project in the CLI and WebUI without a fabricated
behavioral-inertness capability.

## Reserved record root

`.baton/releases` is reserved for Baton's record writer. Product code, build,
test, package, deploy, hooks, and runtime must not read or depend on it.
Product identity ignores exactly this directory.

Plan product scope cannot include the reserved root or its descendants, and a
candidate cannot change it from its exact implementation base. A safe
`scope.exclude` remains valid, preserving immutable historical plans that
already express this boundary.

An unexplained invalid projection is diagnostic and escalation work. It is
never permission for a worker to infer a known limitation or bypass the board.
Implementer guidance also makes explicit that current plan authority comes from
the release ref, even when an unchanged track base retains older record files.

Exact merge-attribute and product-base composition now work with the system Git
shipped on macOS, and ref transactions canonicalize their private temporary
hook path. The record engine runs on macOS CI as part of this release.

## Compatibility

Roles, receipt and schema formats, and lifecycle semantics are unchanged.
Standalone board hosts need no new token or configuration.

Engines embedding the RC9 reference API must remove product-exclusion admission
and behavioral-inertness resolver arguments when adopting RC10. Native ports
must enforce the same structural identity, include, and candidate guards before
claiming RC10.
