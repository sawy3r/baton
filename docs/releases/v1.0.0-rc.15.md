# Baton v1.0.0-rc.15 — compact semantic planning

RC15 helps agents settle the meaning of work before code starts.

The Planner now inspects Git, the current plan, code, tests, docs, and useful
history before asking questions. It finds repository facts itself and asks the
human only about missing choices that could change the promised result. While an
important choice is open, it does not present approval-ready plan bytes.

Once the meaning is clear, the Planner gives the human a short plain-language
summary to correct or confirm. It then writes a compact plan. Each slice promises
one result that can be reviewed alone. Each acceptance claim must be able to fail
in a real product check, and its proposed evidence must observe the boundary it
names. The bundled plan template shows that shape with a concrete CSV export
example.

The Implementer design maps every acceptance ID to an approach and proposed
evidence. It names a missing requirement and stops instead of inventing behavior.
The Captain tries to disprove the approach, returns design gaps for revision,
and names the exact human decision needed when the plan cannot answer a material
question.

Fresh planning trials judge meaning and useful behavior, not exact words or
layout. Those transcripts and reviews are release evidence bound to the exact
candidate and payload; they are not installed files or runtime dependencies.
RC15 adds no role, schema, gate, questionnaire, discovery file, response
snapshot, wording validator, or layout validator.
