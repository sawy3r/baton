# Baton v1.0.0-rc.14 — provider-neutral Git identity

RC14 removes Baton's built-in `Baton Records`, `Baton Receipts`, and
`Baton Merge` author and committer identities.

Every production record-writing action now requires the engine to provide one
explicit Git name and address. Baton validates both before an object-writing
Git command, applies the same identity to author and committer, and never falls
back to repository or global Git configuration. No hosting provider, deployment
provider, service account, or invalid-domain identity is built into Baton.

Identity is attribution metadata only. It does not establish Planner, Captain,
Verifier, Merge, approval, or any other Baton authority. Repeating the same
operation with the same parent, content, timestamp rule, and identity produces
the same object. Using another valid identity may produce another commit object
without changing the projected plan, receipt, candidate, product, or authority
meaning.

Read-only projection remains configuration-free. When historical validation
must reproduce an engine-created composition, it recovers that historical
identity from the applicable commit instead of borrowing today's Git settings.
