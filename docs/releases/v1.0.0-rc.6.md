# Baton v1.0.0-rc.6 — commitment, not inventory

RC6 keeps Baton's five responsibility boundaries and exact Git assurance while
removing a source of avoidable delivery churn.

## What changed

An approved plan now says plainly what it commits:

- observable behavior and product surfaces;
- acceptance and minimum checks;
- semantic limits and hard exclusions;
- authority and externally owned decisions; and
- real delivery dependencies and consumed product.

The plan is not an exhaustive prediction of implementation paths or evidence
commands. Ancillary tests, oracles, support files, additional focused checks,
evidence corrections, and procedural recovery may repair forward under the
same approved plan and stable slice when that commitment is unchanged.

The five portable operations apply the same routing. Bounded Captain
corrections may proceed inline, and Verifier `FAIL` returns the same slice
directly to implementation. Material behavior, consumed-product, contract,
authority, or external-decision changes still stop at the applicable boundary.

## Executable boundary

A real-Git reference journey proves that discovered support paths, an
additional check, exact receipt retry, and evidence correction complete without
a plan revision or replacement work identity. Its paired negative case proves
that material behavior still escalates before implementation.

The reference state and action reducers needed no new lifecycle machinery.
Protected approval, exact bindings, distinct Captain judgement, fresh read-only
verification, fail-closed trust facts, consumed-product pins, and
exact-candidate Merge remain unchanged.

## Compatibility

RC5 and all earlier release candidates remain immutable. RC6 can transactionally
upgrade exact, unmodified RC2, RC3, RC4, and RC5 installations. It adds no role,
state, receipt, schema family, scheduler, inference service, credential custody,
worktree manager, or telemetry system.
