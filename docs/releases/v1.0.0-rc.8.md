# Baton v1.0.0-rc.8 — product-base composition

RC8 removes a false source of replanning and replacement slices. Clean passed
work no longer becomes a composition conflict merely because older delivery
history makes Git choose the wrong merge base.

## What changes for delivery

Previously, misleading repository ancestry could make Git report a conflict
even when the exact passed change still applied cleanly. That forced teams to
replan or replace a slice despite no change in the intended product.

RC8 lets the reference engine reconstruct the passed product's exact baseline
from protected Baton facts and retry that composition. Repairs from earlier
attempts, earlier passed slices in a serial track, and exact consumed inputs
remain part of the result.

Ordinary deterministic composition still runs first. The derived-baseline path
runs only after that ordinary path reports `COMPOSITION_CONFLICT`.

## Fail-closed boundary

The product base comes only from the approved target, ordered prior PASS
products, and exact consumed PASS bindings. Callers cannot supply a raw merge
base, parent, merge strategy, conflict choice, or arbitrary ref.

If the exact passed change still conflicts from that base, Baton returns
`COMPOSITION_CONFLICT` and moves no ref. The result retains the existing
deterministic two-parent shape, keeps the first parent's Baton records exact,
and refuses custom Git merge drivers.

## Compatibility

Existing fast-forward, already-contained, approved-target, clean two-parent
composition, state reconstruction, and exact verification behaviors remain
compatible. No role, operation, receipt contract, schema, lifecycle state,
scheduler, driver, telemetry, inference, or credential feature is added.

RC8 transactionally upgrades exact, unmodified RC2 through RC7 installations.
RC6 and RC7 are admitted only by their immutable tagged package identity and
host-specific ownership fingerprint.
