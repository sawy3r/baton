# Baton v1.0.0-rc.5 — safe upgrades from RC2, RC3, and RC4

RC5 is a narrow installer maintenance candidate. It keeps RC4's protocol,
roles, operations, plan and receipt contracts, board, and autonomous evidence
boundary unchanged.

## What changed

RC4 validated an existing install manifest against only the new
`baton.operation/v2` catalog. Exact RC2 and RC3 installations therefore
stopped before the installer could prove ownership or start its transaction.

RC5 separates current-package generation from predecessor admission:

- the checked-in RC5 generated package is reproduced from the current source
  and catalog before its identity is trusted;
- RC2, RC3, and RC4 are accepted only by exact version, package digest,
  generator, operation version, and host-specific ownership fingerprint;
- the support-package digest is recomputed from every admitted manifest;
- launcher paths, operation attribution, file modes, and created-directory
  claims stay inside the exact owned topology;
- actual installed bytes and modes must still match, and unowned content still
  stops the upgrade; and
- unknown, altered, missing, renamed, or extended ownership claims fail before
  mutation.

Hermetic content-addressed fixtures preserve the real predecessor package
bytes without test-time network or tag access. The regression matrix upgrades
RC2, RC3, and RC4 through both Claude Code and Codex at user and project scope,
preserves unrelated skills, rolls back to the exact predecessor bytes with
`latest`, re-upgrades, and proves the repeated install is a no-op.

The rollback examples now include their required selector:

```sh
./install-claude.sh --user --rollback latest --dry-run
./install-codex.sh --user --rollback latest --dry-run
```

The generated Claude Code and Codex package digest is:

```text

```

## Compatibility and evidence

The RC4 tag and release remain immutable. RC5 supersedes RC4 for installation;
no tag is moved and no old release record is rewritten.

All portable checks must pass on the exact merged candidate before tagging.
All 12 autonomous-engine cases remain `NOT RUN`. Installer success does not
claim that an engine proved scheduling, process isolation, fresh context,
recovery, drivers, telemetry, or final Git effects.
