# Baton v1.0.0-rc.7 — publication recovery

RC7 gives the RC6 protocol a fresh public release identity. The immutable RC6
tag remains part of Baton's history, but its removed GitHub release cannot be
republished under the same name.

## What this release carries

The lean RC6 protocol is unchanged: five responsibilities, compact receipts,
fresh verification, and exact-candidate Merge. Since the RC6 tag, two bounded
maintenance corrections have hardened the reference engine:

- receipts from an earlier release cannot become authority for a later release
  that reuses track or slice names; and
- a track's prepared base includes the currently approved target before design
  or implementation begins.

No role, operation, receipt contract, schema, lifecycle state, scheduler,
driver, telemetry, inference, or credential feature is added.

## Compatibility

RC7 transactionally upgrades exact, unmodified RC2, RC3, RC4, RC5, and
immutable tagged-RC6 installations. The RC6 predecessor is admitted by its
complete package identity and host-specific ownership fingerprint. Unknown,
altered, unowned, or transient RC6-labelled content still fails before
mutation.

## Publication

The RC7 archive is generated reproducibly from the immutable tag. The GitHub
release remains a draft until its archive and checksum have been uploaded,
downloaded again, and verified. Publication does not rewrite or move any
earlier tag.
